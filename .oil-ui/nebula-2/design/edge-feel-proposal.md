# 窗口边界感设计说明：给整个窗口「装裱」

- 任务（2026-11-06，经用户纠偏后重述）：**整个窗口**看着不自然、缺边界感，要更硬朗、更有结构感；**里面的元素和布局很好，不动**。
- 参照物：官方 Minecraft Launcher 新版界面（用户给的第二张截图）——它「边界感控制得很好」。
- 硬约束（用户明示，延续）：
  1. **不改元素**——内部卡片、列表、Tab、按钮、输入框及全部布局坐标一律不动（用户已确认内部很好）；
  2. **不动液态玻璃**——`GlassPanel` 玻璃三层（背景副本 `BlurEffect` / `Tint` / 内容）与背景色块（`GlassBackdrop`，玻璃糊开效果的组成部分）一律不动；
  3. **本次只产出这一份 md 文档**，不实施、不修改仓库任何既有文件。
- 允许动的范围（实施时）：**窗口外壳自身**——窗口圆角、窗口轮廓线、窗口投影、TitleBar 的边界形态、骨架交界线、相关令牌值。

> 理解纠偏记录：上一版把「边界感」落在内部元素描边上，方向偏了。用户澄清：**问题在窗口这一层**——内部的元素和布局本身没有问题。上一版的内部描边方案（列表分隔线、卡片描边、状态描边等）**全部撤下不做**，本文档整体重写为窗口级方案。

---

## 1. 诊断：整个窗口为什么看着不自然

实证（`MainWindow.axaml`）：窗口是 `ExtendClientAreaToDecorationsHint=True` + `ExtendClientAreaChromeHints="NoChrome"` 的**完全自绘无边框窗口**，而后备代码（`MainWindow.axaml.cs`）没有任何圆角 / 轮廓 / 投影 / DWM 处理。也就是说：系统给的窗口边界被主动丢掉了，自绘的窗口边界又从来没补。

| # | 根因 | 证据 | 后果 |
|---|---|---|---|
| 1 | **窗口没有外框**：无圆角、无轮廓线、无投影 | `NoChrome`（`MainWindow.axaml:22-24`），后端零 DWM 调用 | 渐变直接冲到屏幕像素边缘。浅色桌面上窗口「融化」进桌面，深色桌面上又像一张贴片——它不像一个「放在桌面上的窗口」，像一张壁纸或网页 |
| 2 | **四缘 18px 裸渐变带没有归宿** | `Stage` `Margin="18"`（`MainWindow.axaml:52`），而 `BackdropRoot` 铺满全窗 | 这圈内缩带本该是「装裱位」（参考图窗口四边的留白与边线），现在只是无边界的空白渐变，看着像「没对齐」 |
| 3 | **TitleBar 没有「条」的形态** | 标题「版本与实例」与窗口三键直接漂在渐变上（无底、无下沿线） | 窗口缺一个「顶盖」。参考图顶部白色标题条 + 下沿分界线，是整个窗口骨架成立的第一笔 |
| 4 | **骨架交界处只有缝、没有线** | 左竖栏右缘、右详情列左缘、状态条上沿（`Stroke.Subtle` 黑 8%，弱到不可辨） | 顶栏 / 左栏 / 主区 / 底条四块骨架没有被「框」住，结构感散掉 |
| 5 | **窗口三键无依托** | 三键 hover 才有底（`MainWindow.axaml` 窗口三键区） | 悬空的三键加重了「网页感」；参考图三键站在顶栏实体条上 |

**一句话诊断：内部每块玻璃都有自己的框（布局你也认可），唯独最大的容器——窗口本身——什么框都没有。** 不自然感来自最外层：它像一张没有装裱的渐变画。装裱（外框 + 顶盖 + 骨架线）立住，窗口立刻「自然」。

## 2. 参考图拆解：官方启动器的「窗口感」从哪来

| # | 手法 | 参考图证据 | 起了什么作用 |
|---|---|---|---|
| 1 | **窗口是一个实体** | 窗口浮在桌面上，四缘有清晰的边线（圆角 + 细轮廓），与桌面明度/颜色断开 | 这是「边界感」的第一来源：窗口与世界之间有界 |
| 2 | **顶栏实体条** | 顶部白色标题条贯穿全宽，logo / 导航 / 状态 / 三键都站在条上，条有下沿分界 | 给窗口一个顶盖，窗口有了「上梁」 |
| 3 | **四面收边** | 顶栏下沿线、左图标栏右沿线、右栏左沿线、内容区与窗口缘的留白 | 四块功能区被线收进一个完整的「框」里 |
| 4 | **留白即装裱** | 内容不贴窗口边缘，四周有均匀的余量，边线走在余量外沿 | 窗口像被卡纸裱起来的画，而不是内容糊满屏幕 |
| 5 | **窗口圆角小于卡片圆角** | 窗口角≈8，卡片角≈16 | 外框比内容方正——这正是「硬朗、有结构」的形状层级 |

## 3. 方案：给窗口装裱（内部一动不动）

### W1 窗口外框（核心）：圆角 + 1px 轮廓线 + 投影

三件套一次性把「窗口与桌面的边界」立起来：

- **圆角**：`Radius.Md` 12（或 Win11 标准的 8）。窗口圆角**小于**内部卡片圆角（20/24），形成「外框方、内容圆」的硬朗层级（参考图手法 #5）；
- **1px 轮廓线**：窗口内沿一圈 `Stroke.Default`（加深后约黑 22%）——浅色桌面靠它分界，深色主题自动用白系描边；
- **外投影**：贴近型 `0 8 24`（不是现在玻璃卡那种 `0 26 60` 的大虚影），把窗口「抬离桌面」。

三条实现路线（按推荐序）：

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **C·内轮廓（推荐先做）** | 根部加一层「装裱 Border」：`CornerRadius` + 1px `Stroke.Default`，`BackdropRoot` 与 `Stage` 裁进圆角；四角透明露出桌面 | 改动最小（一层 Border + 一处 Clip），立刻有窗口感 | 无外投影；Win10 桌面上圆角靠透明窗口呈现 |
| **B·自绘装裱（最像参考图）** | C + 装裱层 `BoxShadow 0 8 24` 外投影 + 窗口透明（`TransparencyLevelHint`） | 圆角、轮廓、投影全部可控，双主题一致 | **投影必须画在窗口内**：装裱层四缘内缩 ~8px 给投影留空间（正好吃掉现有 18px 裸带的一半）；需核对透明窗口的渲染坑（见 §7） |
| **A·DWM 系统框** | Win11 调 `DwmSetWindowAttribute`（`DWMWA_WINDOW_CORNER_PREFERENCE`）拿系统圆角 + 系统阴影，内沿只补 1px 轮廓线 | 改动集中在后端一处，系统级一致 | 圆角形状由系统定（8px）；Win10 无系统圆角与阴影，会退化为纯轮廓线；多一个平台分支 |

推荐路径：**先 C 后 B**——C 一步就能验证「窗口感」是否到位；要参考图那种浮起感再升 B。A 可以作为 B 之上的 Win11 增强（系统阴影比自绘投影更自然）。

### W2 TitleBar 成「条」：给窗口一个顶盖

布局一动不动（46 高、左标题右三键照旧），只加**边界形态**：

1. **下沿 1px 通栏分界线**（`Stroke.Subtle`）——顶盖成立的第一笔，改动只有一行 XAML；
2. 可选加强：TitleBar 铺一层极浅 tint（`Surface.Glass` 一档），让「条」有面；参考图是白实体条，玻璃语言下用半透明 tint 保持一致；
3. 补上**方向卡已定版但未落地**的一笔：窗口三键与状态胶囊之间 1px 竖分隔线（`glass-direction.md` 窗口控件节：`rgba(10,13,20,.10)`，落成 `Stroke.Subtle`）——执行既定规格，不是新设计。

### W3 骨架交界线：四面收边（只到骨架，不进内部）

| 交界 | 现状 | 改法 |
|---|---|---|
| 状态条上沿 | `UI-STRUCTURE` §2 已定「高≈41，上边框 1px」，现用 `Stroke.Subtle`（黑 8%）不可辨 | 不改代码，`Stroke.Subtle` 加深后自动到位（§4） |
| 左竖栏右缘 / 两列之间 | 只有 12–16px 的缝 | 可选：缝内加 1px 竖线（`Stroke.Subtle`），缝升格为「线 + 缝」。属窗口骨架级；如果觉得里面已经好，可只做状态条与 TitleBar 两条 |
| 窗口四缘 | 18px 裸渐变带 | 不动 `Stage` 的 `Margin="18"`（布局不动），轮廓线走 W1 的装裱层，这一带自然成为「装裱位」（参考图手法 #4） |

### W4 背景与内部：明确不动

- **背景渐变与色块不动**：`GlassBackdrop`（`Gradient.Canvas` + 三个 Blob）是液态玻璃「糊开」效果的组成部分，动它就动了玻璃观感；
- **内部元素与布局全部不动**：卡片、列表、Tab、按钮、输入框、行高、列宽、间距照旧；
- 备注（不默认做）：若 W1–W3 落地后仍觉背景「壁纸感」重，唯一相关的旋钮是把 Blob 色块**向窗内收**（装饰层参数，不动玻璃三层）——需另行拍板，因为那是玻璃规格的背景侧。

## 4. 令牌变更表（Light / Dark 成对，键名不变）

遵守 `tokens.md` 规则：改值不改名、两个 `ThemeDictionaries` 键名完全一致、页面零字面量。

| 键 | Light 现值 → 建议 | Dark 现值 → 建议 | 用途 |
|---|---|---|---|
| `Stroke.Subtle` | `#140F1724` → `#240F1724` | `#14FFFAFA` → `#24FFFAFA` | TitleBar 下沿线、状态条上沿线、三键竖分隔、骨架竖线 |
| `Stroke.Default` | `#240F1724` → `#380F1724` | `#24FFFAFA` → `#38FFFAFA` | 窗口 1px 轮廓线 |
| `Shadow.Window`（**新增**） | `0 8 24 -8 #38103078` | `0 8 24 -8 #B3000000` | 窗口外投影（路线 B；键名两套主题同时加） |
| `Radius.Window`（**新增**，或直接用 `Radius.Md`） | `12` | `12` | 窗口圆角；单独设键是为了「外框比内容方」独立可调 |
| 其余（`Glass.*`、`Surface.*`、`Gradient.*`、内部 `Stroke.Strong`） | **不动** | **不动** | 玻璃与内部已确认良好 |

> 值只动这三个 + 新增两键；`Stroke.Subtle/Default` 的加深同时让窗口骨架线（W2/W3）一次到位，且不影响内部观感——8%→14%、14%→22% 的线只出现在骨架交界处，内部元素的描边本来就是控件级浅边，感知变化很小。

## 6. 验收标准

1. **窗口实体测试**：分别在浅色 / 深色桌面壁纸下截图——窗口四缘有可辨的 1px 轮廓 + 圆角（路线 B 还有投影），窗口不再融进桌面；
2. **25% 缩略图测试**：整窗缩到 25%（约 310×200），一眼看出「一个有顶盖、有边框的窗口」，而不是一片渐变；
3. **顶盖贯通**：TitleBar 下沿线、状态条上沿线贯通全宽、粗细一致，四面收边后窗口骨架（顶栏 / 左栏 / 主区 / 底条）各自可辨；
4. **内部零变化**：内部区域截图与改动前逐像素对比——元素、布局、玻璃质感零变化（只允许骨架线加深带来的既有线材变化）；
5. **双主题一致**：Light / Dark 各出一图，窗口轮廓线在两套主题下都成立（Dark 走白系 `Stroke.Default`）；
6. **窗口行为不变**：拖动（TitleBar 可拖）、三键、1024×660 紧凑档、启动位置恢复（`RestoreWindowState`）全部无回归。

## 7. 冲突与实现注记

| 项 | 说明 | 处置 |
|---|---|---|
| `NoChrome` 下无系统圆角 / 阴影 | Win11 的 DWM 圆角与系统阴影在无边框自绘下默认不出现 | 路线 C/B 自绘补上；路线 A 用 `DwmSetWindowAttribute` 换回系统件 |
| **投影会被窗口边界裁掉** | BoxShadow 画在窗口矩形外的部分不存在 | 路线 B 必须让装裱层内缩 ~8px、投影画在内缩区；`Stage` 现有 18px margin 足够容纳 |
| 透明窗口渲染坑 | `TransparencyLevelHint` 与 `BlurEffect` 副本层、启动闪屏的交互 | 实施前核对 `docs/research/avalonia-glass-controls-20261105.md` 与 `docs/PITFALLS.md` 的窗口条目，路线 C 先行可完全绕开此项 |
| Win10 / Win11 差异 | 路线 A 的系统圆角只有 Win11 有 | 推荐 C/B 自绘，两系统一致；A 只作增强 |
| 窗口圆角 vs 卡片圆角 | 新增 `Radius.Window` 12 小于卡片 20/24 | 这是有意的形状层级（外框方、内容圆），与方向卡「圆角 28/20/14/10」不冲突——后者管内部 |
| 上一版内部描边方案 | 用户确认内部元素与布局很好 | **撤下不做**；其中唯一保留的是 `Stroke.Subtle/Default` 加深——它服务的是窗口骨架线（§4），不是内部 |

## 8. 一句话总结

**问题不在里面，在最外面：系统给的窗口边界被 `NoChrome` 丢了，自绘的又没补——所以整个窗口像一张没装裱的渐变画。** 给窗口加一圈轮廓 + 一个圆角顶盖（TitleBar 下沿线）+ 四面收边的骨架线，内部一动不动，窗口感就回来了。
