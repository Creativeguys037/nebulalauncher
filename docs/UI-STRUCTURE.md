# UI-STRUCTURE.md — 界面结构契约

面向 agent 的界面结构权威文档。**画任何页面前先读这一份**：它规定页面分几层、每一行多高、哪个能滚、控件谁包含谁、什么不许做。

- 视觉方向：已定版样板 `home-glass.html` + `glass.css`（外壳与首页）、`versions-glass.html`（版本页）。本文件**不重新探索风格**，只把结构固定下来。
- 状态：这是**目标态**。逐页实施进度见票 #86–#100；契约本身的来源是票 #102（结构）与 #106（栅格与滚动）。
- 与本文冲突时：以本文为准；本文没覆盖的页内细节，由该页的票补，但不得改变层归属、行划分与控件关系规则。

## 1. 五层视觉模型

| 层 | 内容 | 归属 | 约束 |
|---|---|---|---|
| L0 窗口底 | `Gradient.Canvas` 渐变 | `src/NebulaLauncher.App/Views/MainWindow.axaml` | 不含任何控件 |
| L1 背景副本 | `GlassBackdrop`（渐变 + 三块硬边色块，按窗口比例定位） | 同文件 `BackdropRoot` | **整窗唯一**；用户背景图与遮罩也挂这一层，玻璃卡复制整棵子树才能对齐 |
| L2 玻璃承载 | 外壳竖栏、页面主卡、浮层 | 各页面 | 只有这层用真玻璃（`src/NebulaLauncher.App/Controls/GlassPanel.cs` 的三层） |
| L3 内容 | 文字、图标、输入、列表行、按钮 | 各页面 | 不用模糊；底色只用令牌里的 Surface 家族 |
| L4 浮层 | `DialogOverlay`、Toast、ComboBox Popup | 页面 host | 全页单实例；遮罩阻断下层点击 |

规则：**L2 的玻璃必须透出 L1 的真实背景**。用半透明纯色卡冒充 L2 一律打回——`Border` 在渲染树里只有一层背景，做不出背景副本，所以 L2 只能用 `GlassPanel`。

## 3. 页面固定栅格

页面在 `PageHost` 内占满画布，**自身不滚动**。所有页面同一套四行：

```
UserControl (x:DataType=vm:XxxViewModel)
└─ Grid RowDefinitions="Auto,Auto,*,Auto" RowSpacing="12"      ← 根，不是 ScrollViewer
   ├─ Row0 (40)  页面头       TabControl / 标题行
   ├─ Row1 (48)  工具条       搜索 / 筛选 / 目标选择器
   ├─ Row2 (*)   内容框       GlassPanel → 内部唯一 ScrollViewer（最小高 264）
   └─ Row3 (44)  底栏         批量条 / 结果条（无内容时 IsVisible=false）
```

Row2 的高度不是常数，它由「谁占着位置」决定。**算法（唯一口径）**：

```
Row2高 = 画布高 − Row0 − Row1 − Row3 − 12 × (可见行数 − 1)
```

`RowSpacing` 是 Grid 的固定间距，**不会因为行高塌成 0 就自动消失**。所以折叠行有两种做法，数值差 12：

- **空行合并**（推荐，10 页样板都用这个）：把塌掉的行从 `RowDefinitions` 里去掉 → 可见行数 3 → 间隔 24。
- **固定四行**：保留 `RowDefinitions="Auto,Auto,*,Auto"`，用 `IsVisible=false` 让行高塌 0 → 可见行数仍算 4 → 间隔 36 → Row2 少 12。

两种都合法，但**同一次重排里选一种，别一页一个**。合并口径的实测值：

| Row0 | Row1 | Row3 | Row2（宽屏 677） | Row2（紧凑 537） | 固定四行的同项 | 典型页面 |
|---|---|---|---|---|---|---|
| 40 | 48 | 44 | **509** | **369** | 509 / 369 | 标准四行（#90/#91/#96/#97） |
| 40 | 48 | 0 | **565** | **425** | 553 / 413 | 底栏无内容 |
| 40 | 0 | 44 | **569** | **429** | 557 / 417 | 无工具条（#93 参数栏折叠、#95 表单收起） |
| 40 | 0 | 0 | **625** | **485** | 601 / 461 | 两者都无（#98 一级视图） |
| 40 | 120 | 44 | **449** | **309** | 437 / 297 | 表单展开（#95） |
| 120 | 0 | 96 | **437** | **297** | 425 / 285 | 账户页（#94，Row0 账户卡 + Row3 离线账户） |

一屏可见行数 = `floor((Row2 − 16) / (行高 + 4))`（16 = 内容框上下内边距各 8；4 = 行间距）。**紧凑档不要为凑整行去改内容框内边距**——内边距是基线的一部分，行数不够就承认行数，或者改行高/列宽。

**1024×660 一屏最少 5 行**（行高 56 的标准四行页）。少于这个数说明高度被别处浪费了。

> 票面坐标若与本表冲突：差额 ≤4px 视为取整；>4px 以本表为准，并把该票的坐标段改回来（口径源头在这里，#106 只做 12 页的展开表）。#93 / #94 / #95 的「坐标勘误」评论写的是**固定四行**口径（557 / 425 / 437），样板按**空行合并**口径实现，比它多 12。

### 4.1 页面票落地时的三条统一口径

这三条是补 10 页样板时踩出来的，页面票不要各写各的：

1. **主行动放哪**：内容页（#90 / #91）的 `Button.accent` 在 **Row3 批量条**（批量「启用」），不在 Row1。Row1 的「从文件安装」按票面是 ghost。理由是内容页真正的主行动是「对选中的一批动手」，而批量条只在选中 > 0 时出现——这也满足「一屏一个主行动」。
2. **网格对齐**：皮肤页（#92）的 `*` 列装完固定宽卡片后的余量**居中摊平**，不靠左。宽屏 772 装 4×160+3×12=676，余 96 两侧各 48；紧凑 570 装 3×160+2×12=504，余 66 两侧各 33。票面没定，这里定死。
3. **紧凑档必须妥协时，改高度不改宽度**：皮肤页预览区宽屏 260×320，紧凑档 Row2 只剩 369，320+名称+冷却+操作行放不下，**预览区高度收到 200，宽度仍 260、预览列仍 300**。固定列一律不缩，要缩就缩高度或让框内滚。

## 6. 控件关系规则

1. **一屏一个主行动**：`Button.accent` 同屏只出现一次，其余用 `ghost` / `icon`。
2. **同级视图用 `TabControl`**（胶囊 36，`Surface.Sunken` 底槽）；**筛选**用 `ToggleButton` 组。两者不同屏同时出现，也不共用一个类名。
3. **列表行结构固定**：行容器 → 左信息块（主名 + 副行元数据）→ 右元数据或 ≤3 个行内动作；行内禁止 `accent` 实心按钮。
4. **详情与列表并列**，不叠、不做抽屉；关详情后选中行不丢。
5. **卡片嵌套最多 2 层**，外层 20 内层 12 圆角；hero 28 / 内层 20。
6. **玻璃只在 L2**：外壳、页面主卡、浮层。列表行内部、输入框、日志区一律实心或内凹。
7. **浮层单实例**：`DialogOverlay` 由页面 host 持有，同时只有一个；遮罩用令牌 `Surface.Scrim`（`#66000000`，黑 40%，两套主题共用，见 `src/NebulaLauncher.App/Themes/Tokens.axaml:301`），**不要用 `Surface.Base` / `Surface.Sunken` 这类不透明底冒充遮罩**。
8. **危险动作下沉**：`Button.danger` 不与主行动相邻；删除/覆盖/还原二次确认写清影响范围。
9. **空态必须给下一步动作**，不是一段说明文字。
10. **进度不走弹窗**：行内进度 + 可关闭结果条（成功 N / 失败 M）。
11. **六态齐全**：default / hover / focus / pressed / disabled / loading，缺态视为未完成。
12. **页面零字面量**：不写颜色、字号、圆角、时长；新增令牌 Dark 与 Light 各加一次。

## 7. 滚动边界

1. **页面根不滚动**：根只能是 `Grid` / `Panel`。
2. **固定区不进滚动**：外壳竖栏、TitleBar、Row0、Row1、Row3 在任何滚动下都不动。
3. **滚动必须有框**：`ScrollViewer` 的父容器必须是 `GlassPanel`（1px 可见边）；无框滚动区打回。
4. **一页一条主滚动**：多栏页面每栏各一条，每栏都有框。
5. **空态 / 加载态在框内**：不撑高页面、不产生第二条滚动条。
6. **浮层内可滚但限高**：`MaxHeight` ≤ 画布高的 60%（宽屏 400 / 紧凑 320）。
7. **1024 档不得出现第二条滚动条**：出现即判布局错误，回退去改 `*` 列或减少一屏行数。

## 9. 禁止清单

**结构**

1. 页面根用 `ScrollViewer`（整页滚动）。
2. 一级界面出现窗口整体上下滚。
3. 无边框容器里放 `ScrollViewer`。
4. 用 `Height` 写死页面总高来「制造固定感」。
5. 为塞进固定高度把字号改小（应改列宽或让框内滚动）。
6. 1024 档缩窄固定列（340 / 300 / 160）。
7. 同屏两条纵向滚动条。
8. 把 Row1 工具条也放进滚动区。
9. 负数 `Margin` 让框超出画布。
10. 浮层不限高。

**视觉与控件**

11. 页面里写颜色 / 字号 / 圆角 / 时长字面量。
12. 用 `Border` 冒充玻璃承载（必须 `GlassPanel`）。
13. 同屏两个 `Button.accent`。
14. 用自绘 pill 按钮冒充 `TabControl`；Tab 与筛选按钮同屏同时出现。
15. 列表行内放 `accent` 实心按钮。
16. 详情面板覆盖列表。
17. 卡片嵌套超过 2 层；玻璃卡里套玻璃卡。
18. 危险动作与主行动相邻。
19. 用弹窗表达进度或批量结果。
20. 空态只有文案没有动作。
21. 新增令牌只加 Dark 或只加 Light。
22. 在 `MainWindow.axaml` / `App.axaml.cs` 里塞页面级逻辑；页面里写死除设计件外的宽高。

## 10. 新增或重做页面的流程

1. **先在这份文件加一行**（§4 行分配；新变体先进 §3.1）。文里没有的页面，不许先写 XAML。
2. **补一页最小 HTML 样板**：落在 `.oil-ui/nebula-2/explore/<页面>-glass.html`，文件名进 §12 的索引表。复用 `glass.css`（**不改它、不新增 CSS 变量**），页面专用类写在文件内 `<style>` 的 `PAGE-STYLES` 区；只做首屏结构，不做像素打磨。

   样板的外壳按**现实现**画，不照抄 `home-glass.html` 的 62 高 topbar：左竖栏 82（紧凑 68）+ 46 高 TitleBar + 41 高状态条，页面区是四行栅格，宽屏画布 1100×677、紧凑 898×537。可以直接整段复制脚手架 `.oil-ui/nebula-2/explore/_page-shell.html`（它自带四行栅格、框内滚动、行、空态、骨架的基础样式）。

   两个容易踩的坑：
   - `.glass` 的白色高光 `::before` 是 `z-index:0`，任何内容层必须 `position:relative;z-index:1`，否则文字被压淡。
   - 详情列 / 预览列的固定宽在紧凑档不缩，只缩 `*` 列。

3. **截图自检**（样板的验收方式，不靠肉眼开浏览器）：
   ```powershell
   & "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu `
     --hide-scrollbars --virtual-time-budget=1500 `
     --screenshot="<out>-1240.png" --window-size=1240,800 "file:///<abs>/<页面>-glass.html"
   ```
   同一条命令换 `--window-size=1024,660` 再截一张，然后逐张读图：无溢出 / 无裁切 / 无重叠，四行高度对得上，一屏可见行数达到该页下限。
4. **写票**：写明本页结构树 + 布局坐标（行/高/是否滚动/一屏几行），并引用本文件。
5. **按结构树重排 XAML**：改的是区域与容器层级，允许删掉旧容器与整页 `ScrollViewer`。
6. **双主题 + 1024×660 截图**，与样板并排；结构不一致先改结构，不改像素。

## 13. 窗口三键胶囊与切页动效（草案，待确认）

三键不再是三枚独立按钮，而是收进**一枚 L2 玻璃胶囊**。胶囊在两个位置之间移动：主页停在 TitleBar 搜索框右侧，其余页贴右。回主页时反向复位。

样板：`.oil-ui/nebula-2/explore/pill-glass.html`（`?view=versions` 看切页态，`?seq=return` 走一遍来回）。方案对比：`.oil-ui/nebula-2/design/liquid-glass-options.md`。

### 13.1 结构

```text
TitleBar (46, 可拖动)
├─ .tt      页面标题（22px，不压缩）
├─ .ts      副标题（主页态隐藏）
├─ .tsearch 主页专属搜索框（320×34，其余页 max-width 收到 0）
└─ .wpill   三键胶囊（L2 玻璃，绝对定位 right:0）
   └─ 3 × .wsolid  白色实块 33×29 / 圆角 8 / 间距 4 / 胶囊内边距 4
```

- 三键**实块是白色**（`rgba(255,255,255,.94)`），hover 转主色蓝，关闭键 hover 转危险红。胶囊本身不参与 hover 变色。
- 胶囊 `backdrop-filter: blur(18px) saturate(185%)`，边缘 1px 白边 + 顶边高光（`::after` 内渐变）+ 外部柔光 + 内底阴影。
- 拖窗口用的是 TitleBar 的 `PointerPressed`，胶囊只是它的子元素，不额外接管。

### 13.2 位移算法（这条是落地时最容易错的地方）

**不要量正在动画的搜索框。** 切换那一帧 `.tsearch` 正从 `max-width:0` 展开，`getBoundingClientRect()` 拿到的是起始宽度，胶囊会停在搜索框**左缘**（样板第一版就踩了这个，位移算成 −874 而不是 −551）。

正确做法：按最终布局用常量算。

```text
贴右位置 left = titlebar.clientWidth − pill.offsetWidth
主页位置 left = padding-left + 标题实测宽 + 12 + 320 + 12
位移 dx      = 主页位置 − 贴右位置        （负数，左移）
```

标题宽度可以量（它是 `flex:0 0 auto`，换文案后立即是新宽度，没有过渡）；搜索框宽度**必须用常量 320**，不能量。

### 13.3 时长与曲线

| 动作 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 胶囊横移（两个方向） | **220ms** = `Motion.Normal` | `Motion.EaseOut` = `cubic-bezier(.22,.9,.24,1)` | 与 PageHost 淡入**同长同曲线**，两个方向同值——之前草案里前进 260 / 复位 220 已统一到 220 |
| 页面内容淡入 | 220ms | 同上 | 沿用已有值，不动 |
| 搜索框淡入 / 淡出 | 跟随胶囊 | 同上 | 搜索框只做 `IsVisible` 与透明度，**不做宽度动画**（见 §13.2 的测量坑） |
| 三键 hover 换色 | 120ms | 同上 | 不抢位移的注意力 |

时长与曲线只从 `src/NebulaLauncher.App/Services/Motion.cs` 取，XAML 里用 `{x:Static services:Motion.Normal}` / `EaseOut`，不写字面量——`MainWindow_HasNoPageLevelDesignLiterals` 会抓。

### 13.4 同步规则

1. **胶囊与页面切换同一帧开始**：由同一个触发点同时改视图 `opacity`、标题文案、胶囊 `transform`。胶囊不独立监听导航事件，否则会出现「页面先换、胶囊后到」。
2. **搜索框的收放时长必须等于胶囊时长**：胶囊 220ms 复位、搜索框 260ms 展开，会看到胶囊先到位、框后长出来的错位。
3. 移动中给胶囊加 `.moving`（`scaleX(1.06)`，262ms 后移除），制造「被推着走」的形变；纯位移不像液体。
4. 1024 档三键缩小到 29×25、图标 10（沿用 `Window.compact` 的既有规则），胶囊内边距不变。

### 13.5 降级

真折射（Skia RuntimeEffect 采样背景做边缘弯折）不是本节的必要条件。检测不到 shader 能力时，胶囊退化成上面的「静态玻璃 + 顶边高光」，外观与动效完全不变——**位移逻辑与渲染能力解耦**。
