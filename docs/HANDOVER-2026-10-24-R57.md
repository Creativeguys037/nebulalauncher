# 第五十七轮交接（2026-10-24）

> 主题：资源页「筛选来源」显式化 + 整合包不按游戏版本筛选 + 打通 CurseForge 整合包的查看与下载。
> 本轮只做代码侧验收（构建 + 单测），界面与网络实测由用户执行。

## 0. 用户诉求（原话摘要）

1. 整合包筛选限定了版本，整合包不应该筛选版本，甚至不应该筛选版本；玩家的逻辑是先寻找想要的主题整合包，然后筛选版本，所以整合包筛选版本没有意义。内置 API key 后 CurseForge 的整合包查看和下载能不能做。
2. 资源页面其他程序的自动筛选没有判定来源；玩家应该是先选版本再筛选模组。做成玩家自己选择已经安装的版本或者实例，启动器为玩家选择的实例或者版本下载 mod。

## 1. 决策（已与用户确认）

| 决策点 | 结论 |
|---|---|
| 整合包搜索 | 完全不按游戏版本 / 加载器筛（两站都不筛） |
| 整合包版本列表 | 显示项目全部构建，另加「游戏版本」下拉（默认「全部版本」）；筛选只做本地投影，不重发请求 |
| CurseForge 整合包 | 搜索 + 文件列表 + 项目链接解析 + 下载导入；整合包分区允许「双源」合并 |
| 安装目标下拉内容 | 每个实例 + 每个未建实例的已安装版本 + 全局目录；未建实例的版本落全局 `.minecraft/<内容目录>`，并在副标题写明 |
| 全局目录 | 不筛选版本与加载器（全局目录没有版本身份） |
| 目标记忆 | 仅会话内记忆，不写 `settings.json` |

## 2. 根因（改前行为）

- `LibraryViewModel.ResolveFiltersAsync` 先取「当前内容目标」（`IInstanceContext.GetTargetAsync`），取不到游戏版本时退回
  `AppSettings.LastSelectedVersion`（`ResolveFiltersFromLastVersionAsync`）。玩家在资源页没有做过选择，页面却显示
  「筛选：Minecraft 1.7.10」——来源不可见，也无法在页内改。
- 同一套 `_gameVersion` 被整合包搜索直接复用（`ModpackCatalogClient.SearchAsync(query, gameVersion, …)`），
  于是整合包搜索被当前版本的 `versions:` 分面筛掉，玩家看不到别的版本的同主题包。
- 整合包分区固定 Modrinth：`SelectSourceAsync` / `SelectBothSourcesAsync` 在整合包分区直接早退并显示说明。
  CurseForge 客户端没有整合包入口（`ContentKind` 刻意没有 ModPack 值），classId 4471 未接入。

## 6. 未验证 / 已知限制（实测由用户执行）

- **无真实网络实测**：`classId=4471`、cfwidget `/minecraft/modpacks/{slug}`、CurseForge 整合包 `downloadUrl` 与 `.zip` 导入，只有契约依据 + 假响应覆盖。
- **无界面实测**：下拉框布局、1024×660 换行、整合包版本筛选与「将装到」的交互未截图验证。
- CurseForge 整合包无正文 / 图库详情（现有 CF 卡片都不带详情接口），只有摘要、徽标、版本列表与项目页链接。
- CurseForge 整合包导入仍走 `ModpackService` 的 `files[]` 反查（`GetFilesAsync` 按包声明的 MC 版本 + 加载器过滤后再按 fileID 匹配）；个别文件若不在该过滤结果里会进「待手动安装」清单，与本轮改动前模组导入的既有行为一致。
- 整合包双源不做「整页被去重吃掉就补取」的循环（内容分类路径有）；按页去重，极端重叠时需再点一次「加载更多」。
