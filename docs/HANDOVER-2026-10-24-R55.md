# 第五十五轮交接（2026-10-24）

> 主题：修「微软登录不可用」。R46 把 client id 改成「必须由用户配置环境变量」，
> 结果在不设变量的机器上点「微软登录」直接失败 —— 本轮改为内置 public client id，恢复开箱可登录。

## 0. 根因

用户侧症状：账户页点「微软登录」立刻失败，提示要求先配置 `NEBULA_MS_CLIENT_ID`。

调用链（R46 之后的代码）：

```
AccountsViewModel.SignInMicrosoftAsync
  → AccountService.AddMicrosoftAccountAsync
    → MicrosoftDeviceCodeAuth.SignInAsync
      → ClientId is null → 0 秒早退，不发任何网络请求
```

`clientId` 为空的来源是 `ResolveClientId`：R46 只从 `NEBULA_MS_CLIENT_ID` / `PCL_MS_CLIENT_ID`
两个环境变量读，读不到就返回 null。R46 之所以删掉内置 id，是因为当时内置的
`00000000402b5328` 是 **MSA 旧应用模型**，在 AAD v2 的
`login.microsoftonline.com/consumers/oauth2/v2.0/devicecode` 必然 `AADSTS700016`
（`unauthorized_client`）。结论选错了：问题在「选错了应用」，不在「不该内置」。

## 1. 修法

设备码（device code）是 **public client** 流程：没有 client secret，不需要重定向 URI，
client id 本身就是公开信息。因此可以内置一个在 `consumers` 租户登记过的公共应用 id：

```
fe72edc2-3a6f-4280-90e8-e2beb64ce7e1
```

取值依据：PCL2 正式版二进制（`PCL/最新正式版.zip` → `Plain Craft Launcher 2.exe`）里
UTF-16 字符串 `client_id={0}&tenant=/consumers&scope=XboxLive.signin%20offline_access`
与 `...&client_id=fe72edc2-…&device_code=` 中出现的就是这个值；PCL2 开源版在
`Modules/ModSecret.vb:10` 把它替换成 `PCL_MS_CLIENT_ID` 环境变量。

解析链（优先级从高到低）：

```
构造参数（显式空串 = 禁用）
  → NEBULA_MS_CLIENT_ID
  → PCL_MS_CLIENT_ID
  → DefaultClientId（内置）
```

端点行为单独实测（同类请求，幂等）：

| 请求 | 结果 | 说明 |
|---|---|---|
| `POST /consumers/oauth2/v2.0/devicecode`（内置 id） | 200 + `user_code` | 端点接受该应用 |
| `POST /consumers/oauth2/v2.0/token`（设备码轮询） | 400 `authorization_pending` | 客户端与设备码匹配，等待授权 |
| `POST /consumers/oauth2/v2.0/token`（假 refresh token） | 400 `invalid_grant` | 不是 `invalid_client`，说明 client id 合法 |
| 同上，`client_id=00000000402b5328` | 400 `AADSTS700016` | R46 的原症状复现 |

## 5. 回滚与维护

- 内置 id 若被微软撤回：设 `NEBULA_MS_CLIENT_ID` 覆盖即可，无需改代码重新发版。
- 若需要完全禁用微软登录：显式传空串给 `MicrosoftDeviceCodeAuth` 构造参数（产品侧没有这条入口，仅测试用）。
- 后续可选增强（本轮未做，避免扩大改动面）：设置页提供 client id 输入框，普通用户不必依赖环境变量。
