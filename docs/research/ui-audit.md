# Nebula Launcher 现状 UI 审计（研究笔记）

- 票：#80（父地图 #69）
- 日期：2026-11-02
- 完整报告与证据：`.oil-ui/nebula-2/audit/baseline-report.md`、`.oil-ui/nebula-2/shots/baseline/`（27 张）
- 方法：`tools/shot.ps1` 应用内截图（12 页 × dark/light + 3 张 1024×660），配合 Views/Themes 静态统计与逐页目视。

## 一句话结论

现有界面不是「审美差一点」，而是三层结构同时缺位：**入口过载（一级导航实际 12 项、模组页单屏 14 个工具控件）、控件没有统一状态语言（359 个 Button、19 个 ToggleSwitch 仍是 Fluent 默认、TabControl 使用 0 次）、规范执行不完整（FontSize 硬编码 31 处、CornerRadius 28 处、XAML 转场时长 13 处、Padding 有 66% 不是 4 的倍数）**；「深空/玻璃/微光」的星云渐变 + 半透明卡片 + 蓝紫渐变主按钮，是典型 AI 深色 SaaS 配方，不是产品识别。

## 关键发现

1. **信息重复**：首页账户出现 3 次、版本出现 3 次；账户页当前账户出现 2 次；下载页版本号/日期出现 2 次。
2. **卡片同质**：Hero、统计、快捷入口、世界、设置全部是同一套 `Border.card` + 18px 内边距，层级只靠尺寸，不靠信息角色。
3. **控件不统一**：Button 359 次、高度 30/32/34/36/40/44/48 七档；ToggleSwitch/ComboBox/TextBox 仍是 Fluent 默认皮肤；页签全部用 Button 模拟（TabControl 0 次）。
4. **规范执行不完整**：Views 颜色字面量 0（好），但 FontSize 字面量 31 处、CornerRadius 28 处、Duration 13 处硬编码；`Tokens.axaml` 的 45 个双主题键名一致，工程底子在。
5. **1024×660 不达标**：侧栏「世界」被常驻皮肤卡挤出导航可视区；首页快捷卡、版本第 4 行、下载「安装摘要」在首屏被裁。
6. **AI 感来源明确**：全屏蓝紫星云渐变、玻璃卡片 + 亮描边、蓝紫渐变主按钮、彩色字母块图标、11–12px 灰色元信息承载判断依据。

## 规范体检

- **品牌资产（保留）**：深空蓝黑底 `#080B12`、蓝紫主色 `#4C6FFF`/`#A855F7`、双主题令牌体系（45 键完全一致）、细描边 + 低阴影、中文 MC 领域文案、SVG path 图标、状态色四档 + Soft 底、侧栏 3D 皮肤卡（需缩小/可折叠）。
- **偶然默认值（可推翻）**：全屏 Aurora 四色光斑、卡片海洋、胶囊万能控件（Skins 26 / Versions 25 / Settings 16）、每行一个 accent 主按钮（Versions 11 个）、设置页双层侧栏、1240×800 固定网格、8 档字号、`Palette.*` 与主题字典重复维护。
- **「深空/玻璃/微光」的具体 AI 感元素**：`AuroraBackground` 的蓝/紫/青/蓝四光斑（深色 alpha 0.34/0.30/0.26/0.20）；6% 透明白卡片叠在渐变上，每张卡颜色不同；`Gradient.Accent` 蓝紫按钮；彩色首字母/字母块图标；`Shadow.Glow` 霓虹边；11px 灰字说明；每页重复的「胶囊筛选 + 搜索 + 动作胶囊」三件套。

## 对重制的直接输入

- 一级入口从 12 个收敛到 6–7 个，皮肤并入账户，设置分区改单层。
- 首屏只保留一个主行动，账户/版本/统计/快捷入口不重复。
- 建立共享列表行/工具栏/状态条/页签组件，替代页面内联样式。
- 颜色改为哑光结构色 + 单一信号色；去掉全屏渐变背景。
- 间距/字号/圆角落到令牌；动效统一走 `Motion.Dur`（先解决 XAML `Transitions.Duration` 的 TimeSpan 类型问题）。
