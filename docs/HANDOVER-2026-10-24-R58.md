## 0. PCL2 对照

### 0.1 整合包 → 独立版本目录

PCL2（`Modules/Minecraft/ModModpack.vb`）：

- `:31-40`：`TargetFolder = McFolderSelected\versions\{InstanceName}`，实例目录就是版本目录；
  目录名非法或已被占用时让用户重新输入名称（`ValidateFolderName`）。
- `:162-190` / `:366-405`：CurseForge / Modrinth 包的实例名来自包内 `name`，随后按同一规则落盘。

本轮实现（`ModpackService`）：

- 版本目录名 = 整合包实例名（不再用「已安装的共享游戏版本名」）；重名自动追加 ` (2)`、` (3)`。
- 游戏本体仍只装一份共享版本；实例版本写 `versions/<实例名>/<实例名>.json`：
  `{ id, inheritsFrom: 共享版本名, type: "release", time, releaseTime, libraries: [], arguments: { game: [], jvm: [] } }`，
  文件由 CmlLib 沿 `inheritsFrom` 链补全——与 `InstallService` 写加载器 profile 是同一机制。
- 未装游戏（开关关闭 / 无安装服务 / 包不需要装游戏）时不写版本 json，结果文案仍说明「未安装游戏」。
- 装成功但拿不到父版本名（Forge / NeoForge 没有 marker 且推不出目录名）时同样不写版本 json，
  并把 `GameInstalled` 报成 false——实例启动会被前置检查挡下，不能给一个看似成功的结果。

与 PCL2 的差异：

- PCL2 目录名冲突时弹框让用户输入；这里没有输入框，自动加序号（`Pack A (2)`），`InstanceInfo.Name` 同步用唯一化后的名字。
- PCL2 的版本 JSON 由它自己写全量字段；这里只写增量，依赖 CmlLib 的继承合并（已验证于加载器 profile 这条既有链路）。

### 0.2 双源分页（PCL2 的 TargetResultCount 循环）

PCL2（`Modules/Resource/ResourceSearcher.vb`）：

- `:333` / `:376`：`CurseForgeOffset` / `ModrinthOffset` 各自按**实际返回条数**推进。
- `:470-476`：`RealResults.Count + Storage.Results.Count < TargetResultCount` 且可继续且无错误时 `GoTo NextPage`。
- 目标条数来自 `(Page + 1) * PAGE_SIZE`（`PageResource.xaml.vb:122`）。

本轮实现（`LibraryViewModel`）：

- 新增 `_modrinthOffset` / `_curseForgeOffset`，两站独立推进；`HasMore = 任一未耗尽`。
- 一次「加载更多」的目标是新增一页；去重后不足一页且仍可继续时补取，最多补 2 页
  （`BothSourcesMaxExtraPages`）。内容分类与整合包分区共用同一口径。
- 重置点：`SearchCoreAsync(reset)` / `SearchModPacksAsync(reset)` 把两个偏移与耗尽标记一起清零。

与 PCL2 的差异：PCL2 用服务端 `totalCount` 判「还有没有后续」，这里用「本次返回不足一页」；
PCL2 一次请求加载到 `(页+1)×页大小`，这里每次点击只目标一页。

### 0.3 跨站去重（PCL2 的 IsLike）

PCL2（`Modules/Resource/ResourceProject.vb`）：

- `:179-196`：CurseForge 项目从 `latestFiles[].gameVersions` 与 `latestFilesIndexes[]` **并集**聚合版本与加载器。
- `:664-694`：判据顺序为「同源拒绝 → 加载器一致 → 一周内更新 → 非光影版本一致 → 名称 / 描述 / slug」。

本轮实现（`CrossSourceSearch`）：

- `SearchProjectInfo` 新增 `Loaders`；CurseForge 侧由 `ParseSearch` 从 `latestFiles` 与 `latestFilesIndexes`
  **并集**聚合 `GameVersions` / `Loaders`（与 PCL2 一致），Modrinth 侧从 `categories` 取加载器。
- `IsSameProject` 按上述顺序重写：两边都有加载器才比较；版本判据只要求
  **CurseForge 集合 ⊆ Modrinth 集合**（CF 只能看到最近若干文件，MR 是项目全集；要求完全相等会把同一项目判成不同）。
  名称规范化 / slug 规范化 / 描述完全相同任一命中即视为同一项目，规范化后为空不算命中。

与 PCL2 的差异：

- PCL2 `:680` 写的是「版本集合 `SequenceEqual` 才拒绝」，与 `:679` 注释「要求 MC 版本一致」相反；
  这里按注释意图实现，并把「完全相等」放宽为「CF 是 MR 的子集」（理由见上）。
- PCL2 直接比 `ModLoaders` 位标志；这里「两边都非空才比」，避免 CF 缺加载器数据时把所有配对拒光。
- PCL2 有 MCMOD 译名判据，本仓库无该数据源，不实现。
- PCL2 的 Modrinth 侧同时读 `loaders` 与 `categories`；本仓库 `ModrinthProject` 只建模了 `categories`。

## 3. 未验证 / 已知限制（实测由用户执行）

- **继承版本在 CmlLib 上的可用性**：依据是本机 NuGet 包 `CmlLib.Core 4.1.0` 的只读反编译
  （`inheritIfRequired`、`GetInheritedProperty`、逐层提取文件），与 `InstallService` 写加载器 profile 是同一条链路；
  未真实启动验证。
- **每个整包首次启动会补一份客户端 jar**：继承版本没写 `jar` 字段，CmlLib 会把 `downloads.client` 补到
  `versions/<实例名>/<实例名>.jar`（约 20MB，形态与 Forge 版本目录一致）。
  `PreflightChecker` 在这份 jar 补齐前会给一条「加载器版本缺 jar」的非阻断告警。
- **父版本名拿不到时不写版本 json**：Forge/NeoForge 的安装产物没有 `nebula-loader.json` marker 且无法推出名字时，
  实例会指向一个没有版本 json 的目录（启动会报「版本未安装」）。该路径会写 Warning，导入结果报 `GameInstalled=false`，
  UI 红条提示「到版本页完成安装」。
- **CurseForge 版本集合仍可能比 Modrinth 小**：已改为 `latestFiles` ∪ `latestFilesIndexes` 并把版本判据放宽为「CF ⊆ MR」；
  若 CF 搜索结果里两个数组都只覆盖少数文件，仍可能判成不合并（保守方向）。
- **无真实网络实测**：`latestFiles` / `latestFilesIndexes` 的真实响应形态、classId=4471、cfwidget `modpacks` 段均按接口文档 + 假响应覆盖。
- 唯一化命名是「检查 → 创建目录」的 TOCTOU，未加锁；并发导入同名整包的窗口极小，本轮不处理。
