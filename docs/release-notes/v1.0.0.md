# Nebula Launcher v1.0.0

首个正式版，2026-10-24 发布。本文件由 `gh release create v1.0.0 --notes-file docs/release-notes/v1.0.0.md` 直接读取（`CONVENTIONS.md` §8.7）。

## 一、概览

Nebula Launcher 是一个以 Windows 为首发验证平台的 Minecraft Java 版桌面启动器：原生 Avalonia 界面，不内嵌 WebView，把版本安装、实例与模组管理、启动、崩溃诊断收在同一个窗口里。

### 本版包含

1. **装得上**：原版与 Fabric / Quilt / Forge / NeoForge 安装，装坏了能就地修复。
2. **下得动**：多源并发下载，官方源不通时自动降级到 BMCLAPI 镜像。
3. **开得起来**：实例隔离启动，Java 版本探测、缺 Java 时一键安装，内存与参数自动算。
4. **管得住内容**：Modrinth + CurseForge 双源搜索与下载，模组扫描与启停，整合包导入导出，资源包与光影包归类。
5. **存得下**：实例、世界与备份都落在磁盘上，删除进回收站可捞回。
6. **连得上**：离线 / 微软设备码 / authlib-injector 三种账户；服务器收藏与 Server List Ping。
7. **看得见**：日志实时查看，崩溃导出成可分享的包，附崩溃归因提示。
8. **改得动**：主题、托盘、设置导入导出，实例可切换加载器。

### 系统要求

- Windows 10 1809 及以上 / x64。
- zip 形态需要 .NET 8 Desktop Runtime（<https://dotnet.microsoft.com/download/dotnet/8.0>）；便携单文件形态自带运行时，不需要。
- 至少 200 MB 可用空间，游戏版本与实例另计。
- 启动 Minecraft 需要对应版本的 Java；启动器可在缺 Java 时一键安装。

对外版本号一律 `v1.0.0`，唯一来源是 `Directory.Build.props:9` 的 `<Version>1.0.0</Version>`；设置页「关于」与崩溃导出的 `system.txt` 显示同一串。

### 安装与运行

- **zip**：解压到任意可写目录，双击 `NebulaLauncher.exe`。目标机缺 .NET 8 Desktop Runtime 时 Windows 会提示安装；装好后不需要 `%TEMP%` 写权限。
- **portable exe**：放到任意目录双击，无需解压、无需运行时。首次启动把原生库解压到 `%TEMP%\.net\NebulaLauncher\`；该目录被安全软件拦截时启动会直接失败，改用 zip。若 `%TEMP%` 写在被策略限制的位置，设置环境变量 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向一个可写目录即可。
- 两种形态共用同一份数据目录（默认 `%APPDATA%\NebulaLauncher`），可以互换使用。

## 三、已知限制

以下 8 条在 v1.0.0 的代码里确认存在，也是本版真正的功能缺口。每条后面的括号是代码位置指针。

1. **页面切走后旧页面的后台任务不回收。** 实例页、模组页打开定时刷新后切到别的页面，旧页面的定时器与订阅不会被拆掉；长时间来回切换会表现为刷新变密或偶发卡顿（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:327` `InvalidatePageCache()`）。
2. **快速连点导航时页面钩子可能交错。** 上一下一页的进入 / 离开准备工作是异步发起、不等结果的，连点左侧导航时偶发数据晚一拍，切换过快时看到的是上一页的旧数据（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:649` `RunPageLifecycleAsync`）。
3. **反复进出账户页会累积监听。** 账户变化通知的订阅只在页面销毁时退订，而缓存失效的路径不销毁页面，进入账户页次数越多，监听越多（`src/NebulaLauncher.App/ViewModels/AccountsViewModel.cs:265` `Dispose`）。
4. **启动器运行中手改账户文件不生效。** 直接编辑 `accounts.json` 后，界面不会重新加载，需要重启启动器（`src/NebulaLauncher.Core/Abstractions/AccountServices.cs:47` `ReloadAsync`、`src/NebulaLauncher.Core/Accounts/AccountService.cs:108`）。
5. **按文件夹放开的资源包不被识别。** 资源包列表只认 `.zip` 与 `.resourcepack` 文件；把资源包解包成 `resourcepacks/<名字>/` 文件夹后不进列表（`src/NebulaLauncher.Core/Mods/ContentService.cs:1193` `ScanFiles`、`:1252` `IsContentFile`）。
6. **并发导入同名整合包可能撞名。** 实例名唯一化是先查后建，两个同名整包同时导入的极端时序下会撞到同一个版本目录名（`src/NebulaLauncher.Core/Backups/ModpackService.cs:1798` `ResolveUniqueVersionName`、`:1843` `IsVersionNameTaken`）。
7. **继承型整包首次启动要补下载 client jar。** 导入的整包若引用原版版本，首启前会补一个约 20 MB 的 client jar，启动前有一条警告提示，进度停在准备阶段属于正常（`src/NebulaLauncher.Core/Backups/ModpackService.cs:584` `WriteInheritedVersionJsonAsync`；告警来自 `src/NebulaLauncher.Core/Launching/PreflightChecker.cs:417` `CheckLoaderAsync`）。
8. **换账户后实例面板的认证服务器文案滞后。** 已打开的实例设置面板仍显示上一个账户「跟随账户」的认证服务器，关掉面板重开或重启启动器后正确（`src/NebulaLauncher.App/ViewModels/VersionsViewModel.cs:1953` `EditorAuthServerHint`）。

## 四、证据链与签名说明

### 签名状态

本版可执行文件未使用代码签名证书签名，因此 Windows 可能显示「Windows 已保护你的电脑」。请用上一节的 SHA256 核对文件完整性后再决定是否运行（右键 → 属性 → 数字签名 为空属预期）。

### 发布可见性

仓库为私有仓库，未登录状态下访问本 Release 的网页地址返回 404，属预期；附件仅对拥有仓库访问权限的成员可见。

### 产物自检

两道产物自检都在构建时执行，未使用 `-SkipVerify`：`--probe-dir` 断言数据目录可写并输出 `writable=YES`；`--screenshot` 要求 20 秒内退出且 PNG 大于 10240 字节，实测 zip 形态 145,751 字节、portable 形态 145,683 字节。portable 的这两道自检在构建机直接运行时被 `%TEMP%` 下的解压目录拦下，设置 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向可写目录后两道都通过，因此便携版的运行前提就是该解压目录可写。

### 必测七项与执行人

发布前按下列七项验收，任一不通过即不发版：

| # | 项目 | 执行人 | 判据 |
| --- | --- | --- | --- |
| 1 | 冷启动到首页 | 子代理 | shot.ps1 的 `-Page home -Theme dark` 与 `-Theme light` 各 exit 0，PNG 各大于 10240 字节 |
| 2 | 装一次原版实例 | 用户 | 实例进列表，`versions/<名>/` 下有版本 json 与 client jar |
