# Nebula Launcher v1.2.0

v1.1.1 之后的功能版，2026-11-02 发布。皮肤站（LittleSkin）的云端衣柜新增 **OAuth 设备码免密登录**：不用把皮肤站密码交给启动器，也能登录、读取角色、应用与清除衣柜里已有的材质。其余页面与既有账号体系未改。

## 一、概览

**票 #60：皮肤站无密码登录（OAuth 设备代码流）。**

背景：v1.1.0 起云端衣柜用皮肤站账号 + 网页会话工作，密码经 DPAPI 加密存在本机。本版补上第二条通道：走 Blessing Skin 的 OAuth 设备代码流，登录时只显示一个 6 位授权码，由用户在站点点确认。

- 设备码：`POST https://open.littleskin.cn/oauth/device_code`（client_id 1674，scope `openid User.Read Player.ReadWrite Closet.Read offline_access`），展示 `user_code` 并打开 `verification_uri_complete`。
- 轮询：按 `interval`（5 秒）轮询 `/oauth/token`；`authorization_pending` 继续、`slow_down` 退避、`expired_token` / `access_denied` 停止并提示重新发起。
- 调用：拿到 token 后走 Bearer —— `GET /api/user`、`GET /api/players`、`GET /api/closet`、`PUT`/`DELETE /api/players/{pid}/textures`；HTTP 200 但 JSON `code` 非 0 时同样按失败处理并透出站点消息。
- 续期：access token 过期前 60 秒自动用 refresh token 换新；401 时强制刷新并重试一次；刷新后整组替换并写回本机凭据。
- 存储：access / refresh token 与密码一样经 `TokenProtector`（Windows DPAPI）加密，落在 `skin-site-credentials.json`，不写日志。
- 边界：免密模式只应用 / 清除衣柜里**已有**的材质。上传新 PNG、删除云端材质仍只走账号密码的网页会话（JSON API 没有这两个端点），界面按钮会禁用并说明原因。

主要改动：`src/NebulaLauncher.App/Skinning/CloudClosetClient.OAuth.cs`（新增，601 行）、`CloudClosetClient.cs`、`CloudClosetViewModel.cs`、`CloudClosetView.axaml`、`src/NebulaLauncher.Core/Skinning/SkinSiteCredentialStore.cs`；新增测试 `tests/NebulaLauncher.Tests/AppSkin_CloudClosetOAuthTests.cs`（10 例）与凭据存储 2 例。提交 `5fa7a8c`。

## 二、安装与体积

体积在本机 win-x64、Release 配置下由 `build.ps1 -Publish` 构建、`tar -a -c` 打包后实测（2026-11-02，发布号 `v1.2.0`）。数字随 .NET 运行时版本与构建机变化。

| 附件 | 形态 | 实测体积 | 文件数 | 前提 |
| --- | --- | --- | --- | --- |
| `NebulaLauncher-v1.2.0-win-x64.zip` | 框架依赖 + 单文件，原生库外置 | 压缩包 27,340,800 字节；解压后 27,334,442 字节 | 解压后 3 个 | .NET 8 Desktop Runtime |
| `NebulaLauncher-v1.2.0-win-x64-portable.exe` | 自包含 + 单文件 + 裁剪压缩 | 25,612,256 字节（单文件，无解压步骤） | 1 个 | 无 |

zip 解压后 3 个文件：`NebulaLauncher.exe` 16,115,354 字节 + `libSkiaSharp.dll` 9,414,216 字节 + `libHarfBuzzSharp.dll` 1,804,872 字节。

- **zip**：解压到任意可写目录，双击 `NebulaLauncher.exe`。目标机缺 .NET 8 Desktop Runtime 时 Windows 会提示安装；装好后不需要 `%TEMP%` 写权限。
- **portable exe**：放到任意目录双击，无需解压、无需运行时。首次启动把原生库解压到 `%TEMP%\.net\NebulaLauncher\`；该目录被安全软件或策略拦截时启动会直接失败，改用 zip，或设置环境变量 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向一个可写目录。
- 两种形态共用同一份数据目录（默认 `%APPDATA%\NebulaLauncher`），可直接覆盖旧版使用；已保存的皮肤站账号、免密令牌与皮肤库不受影响。

## 三、已知限制

1. **免密模式不能上传新材质，也不能删除云端材质。** OAuth JSON API 没有对应端点（`src/NebulaLauncher.App/Skinning/CloudClosetClient.cs` 的 `UploadTextureAsync` / `DeleteTextureAsync` 在 OAuth 会话下直接拒绝）。需要上传 PNG 时请改用账号密码登录。
2. **应用默认是测试模式。** 设备代码流白名单应用初始只允许创建者账号授权；其他用户要等站方解除测试模式。这是站点侧配置，不是启动器行为。
3. **scope 需要实际调用验证。** `/oauth/device_code` 端点不校验 scope，申请即返回 200；`Player.ReadWrite` 是否真的授予，只能等授权后看站点权限页，或用 `GET /api/players` 是否成功来间接判断。失败时界面会提示「应用可能没有获得对应权限」。
4. **真账号冒烟未完成。** 本版实现与离线测试均已完成，但「真实账号授权 → 应用材质 → 游戏内生效」这条链路没有在当前构建上人工跑过（票 #60 的维护者决定先发版）。若你遇到授权页无「读写角色与材质」、或应用返回 403，请把票 #60 的验收清单回帖补上。
5. 沿用 v1.1.1 的其他限制，见 `docs/release-notes/v1.1.1.md` 第四节。
