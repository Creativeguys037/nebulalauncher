# Nebula Launcher v1.0.1

v1.0.0 之后的补丁版，2026-10-25 发布。唯一主题是 GitHub issue #26 的修复：`portable` 单文件裁剪发布把 System.Text.Json 的反射序列化元数据整块关掉，设置保存与读取、账户、实例、整合包、备份、Java 缓存、收藏等所有 JSON 落盘通路在便携版里都失效。本文件由 `gh release create v1.0.1 --notes-file docs/release-notes/v1.0.1.md` 直接读取（`CONVENTIONS.md` §8.7）。

## 一、概览

Nebula Launcher 是一个以 Windows 为首发验证平台的 Minecraft Java 版桌面启动器：原生 Avalonia 界面，不内嵌 WebView，把版本安装、实例与模组管理、启动、崩溃诊断收在同一个窗口里。

### 本版包含

1. **修复 #26：便携版的 JSON 落盘通路全部恢复。** 现象是便携版里设置存不住、账户与实例读不回、整合包与备份落不了盘、Java 缓存与收藏失效——凡是把对象写成 JSON 落到磁盘的通路都断了。修法是把全仓 19 处 `JsonSerializerOptions` 与 55 个调用点迁到 System.Text.Json Source Generator：每个落盘类型在定义它的文件尾登记一个带 `[JsonSerializable]` 的 `JsonSerializerContext`，调用点统一经 `src/NebulaLauncher.Core/Serialization/JsonMeta.cs:30 JsonMeta.Of` 取这份 options 的编译期元数据。
2. **调用点各自的 options 口径没有被换掉。** `JsonSerializerContext` 的 `Default` 用的是生成器口径，直接拿它会丢掉 camelCase、大小写不敏感、枚举字符串转换器等开关，落盘字段名与旧文件对不上。最终实现走 `options.Of` 这条路取「按这份 options 固化好的元数据」，`docs/PITFALLS.md` 记录了该坑与反证。
3. **发布自检从两道关扩到三道关。** 新增第 2 关 `--selftest-json`：在真实裁剪产物里跑七条 JSON 落盘往返，判据是 120 秒内退出码 0、输出无 `json-selfcheck.FAIL`、且 `json-selfcheck.summary=7/7`（`src/NebulaLauncher.Core/Diagnostics/JsonSelfCheck.cs:32 JsonSelfCheck.RunAsync`）；`--probe-dir` 与 `--screenshot` 照旧。此前两道关只验「能不能跑」与「能不能渲染」，这类坏产物能连过两关。
4. **漏改拦在编译期。** `src/NebulaLauncher.Core/NebulaLauncher.Core.csproj:10 IsAotCompatible` 打开后，反射与动态代码依赖在 `dotnet build` 期就报出来（`IL2026` / `IL2072` / `IL3050`），不必等发布包运行才炸。

### 系统要求

- Windows 10 1809 及以上 / x64。
- zip 形态需要 .NET 8 Desktop Runtime（<https://dotnet.microsoft.com/download/dotnet/8.0>）；便携单文件形态自带运行时，不需要。
- 至少 200 MB 可用空间，游戏版本与实例另计。
- 启动 Minecraft 需要对应版本的 Java；启动器可在缺 Java 时一键安装。

对外版本号一律 `v1.0.1`，唯一来源是 `Directory.Build.props:9` 的 `<Version>1.0.1</Version>`；它同时决定 AssemblyVersion、FileVersion 与 InformationalVersion，设置页「关于」与崩溃导出的 `system.txt` 显示同一串，发布 tag 与发布目录名也跟着它走。

### 附件与实测体积

体积在本机 win-x64、Release 配置下由 `build.ps1 -Publish` 构建时打印（2026-10-25，tag `v1.0.1`）：

zip 解压后 {{MINIMAL_ZIP_FILES}} 个文件、合计 {{MINIMAL_EXTRACTED_BYTES}} 字节：可执行文件 `NebulaLauncher.exe` 加两个原生库 `libSkiaSharp.dll` 与 `libHarfBuzzSharp.dll` 的合计。便携形态没有解压步骤，{{PORTABLE_EXTRACTED_BYTES}} 字节就是那个单文件 exe。这些数字随 .NET 运行时版本与构建机变化。

### 安装与运行

- **zip**：解压到任意可写目录，双击 `NebulaLauncher.exe`。目标机缺 .NET 8 Desktop Runtime 时 Windows 会提示安装；装好后不需要 `%TEMP%` 写权限。
- **portable exe**：放到任意目录双击，无需解压、无需运行时。首次启动把原生库解压到 `%TEMP%\.net\NebulaLauncher\`；该目录被安全软件或策略拦截时启动会直接失败，改用 zip，或设置环境变量 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向一个可写目录。
- 两种形态共用同一份数据目录（默认 `%APPDATA%\NebulaLauncher`），可以互换使用。
- 可执行文件未签名，Windows SmartScreen 会弹「已保护你的电脑」：点「更多信息」，再点「仍要运行」。

## 三、已知限制

以下 8 条在 v1.0.1 的代码里确认存在，也是本版真正的功能缺口。每条后面的括号是代码位置指针。

1. **页面切走后旧页面的后台任务不回收。** 实例页、模组页打开定时刷新后切到别的页面，旧页面的定时器与订阅不会被拆掉；长时间来回切换会表现为刷新变密或偶发卡顿（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:327 InvalidatePageCache`）。
2. **快速连点导航时页面钩子可能交错。** 上一下一页的进入 / 离开准备工作是异步发起、不等结果的，连点左侧导航时偶发数据晚一拍，切换过快时看到的是上一页的旧数据（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:649 RunPageLifecycleAsync`）。
3. **反复进出账户页会累积监听。** 账户变化通知的订阅只在页面销毁时退订，而缓存失效的路径不销毁页面，进入账户页次数越多，监听越多（`src/NebulaLauncher.App/ViewModels/AccountsViewModel.cs:265 Dispose`）。
4. **启动器运行中手改账户文件不生效。** 直接编辑 `accounts.json` 后，界面不会重新加载，需要重启启动器（`src/NebulaLauncher.Core/Abstractions/AccountServices.cs:47 ReloadAsync`；实现见 `src/NebulaLauncher.Core/Accounts/AccountService.cs:108 LoadAsync`）。
5. **按文件夹放开的资源包不被识别。** 资源包列表只认 `.zip` 与 `.resourcepack` 文件；把资源包解包成 `resourcepacks/<名字>/` 文件夹后不进列表（`src/NebulaLauncher.Core/Mods/ContentService.cs:1183 ScanFiles`、`src/NebulaLauncher.Core/Mods/ContentService.cs:1242 IsContentFile`）。
6. **并发导入同名整合包可能撞名。** 实例名唯一化是先查后建，两个同名整包同时导入的极端时序下会撞到同一个版本目录名（`src/NebulaLauncher.Core/Backups/ModpackService.cs:1798 ResolveUniqueVersionName`、`src/NebulaLauncher.Core/Backups/ModpackService.cs:1843 IsVersionNameTaken`）。
7. **继承型整包首次启动要补下载 client jar。** 导入的整包若引用原版版本，首启前会补一个约 20 MB 的 client jar，启动前有一条警告提示，进度停在准备阶段属于正常（`src/NebulaLauncher.Core/Backups/ModpackService.cs:588 WriteInheritedVersionJsonAsync`；告警来自 `src/NebulaLauncher.Core/Launching/PreflightChecker.cs:417 CheckLoaderAsync`）。
8. **换账户后实例面板的认证服务器文案滞后。** 已打开的实例设置面板仍显示上一个账户「跟随账户」的认证服务器，关掉面板重开或重启启动器后正确（`src/NebulaLauncher.App/ViewModels/VersionsViewModel.cs:1953 EditorAuthServerHint`）。

## 四、证据链与签名说明

### 签名状态

本版可执行文件未使用代码签名证书签名，因此 Windows 可能显示「Windows 已保护你的电脑」：首次运行点「更多信息」→「仍要运行」。请用上一节的 SHA256 核对文件完整性后再决定是否运行（右键 → 属性 → 数字签名 为空属预期）。

### 发布可见性

仓库为私有仓库，未登录状态下访问本 Release 的网页地址返回 404，属预期；附件仅对拥有仓库访问权限的成员可见。发布命令只建草稿（`--draft`），「Publish release」由人在网页点。

### 产物自检

三道产物自检都在构建时执行，未使用 `-SkipVerify`：

- 第 1 关 `<out>\NebulaLauncher.exe --probe-dir <out>`：30 秒内退出码 0，输出含 `writable=YES`。
- 第 2 关 `--selftest-json`（本版新增）：120 秒内退出码 0、输出无 `json-selfcheck.FAIL`、且 `json-selfcheck.summary=7/7`；它真跑七条 JSON 落盘往返（`src/NebulaLauncher.Core/Diagnostics/JsonSelfCheck.cs:32 JsonSelfCheck.RunAsync`）。
- 第 3 关 `--data-dir <out>\.verify --screenshot <out>\.verify.png --page home`：20 秒内退出码 0 且 PNG 大于 10240 字节。

第 2 关把单文件解包目录钉在产物目录（`DOTNET_BUNDLE_EXTRACT_BASE_DIR`），它的结论只反映产物本身，不受 `%TEMP%\.net` 可写性影响。
