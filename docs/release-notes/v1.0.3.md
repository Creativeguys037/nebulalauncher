# Nebula Launcher v1.0.3

v1.0.2 之后的补丁版，2026-10-25 发布。本版只有一处用户可见改动：GitHub issue #28 的修复——报告者反馈「首页账户卡片把第三方验证账户显示成离线账户」。这不是显示瑕疵，而是同一个账户在不同页面上被认成了两种登录方式。修复把三处各自判定的文案收敛成唯一一份映射，随本版一并删掉了重复实现。本文件由 `gh release create v1.0.3 --notes-file docs/release-notes/v1.0.3.md` 直接读取（`CONVENTIONS.md` §8.7）。

## 一、概览

Nebula Launcher 是一个以 Windows 为首发验证平台的 Minecraft Java 版桌面启动器：原生 Avalonia 界面，不内嵌 WebView，把版本安装、实例与模组管理、启动、崩溃诊断收在同一个窗口里。

### 本版包含

1. **修复 #28：第三方验证账户不再被首页显示成「离线账户」。** 现象是账户页大卡片明明写着「第三方验证」，切到首页账户卡片却显示「离线账户」，而该账户实际走的是自建的 authlib-injector 验证服务器，登录行为与离线账户完全不同——用户据此会误判当前用的是哪个账户。成因是三处界面各写一份判定：账户类型本有三态（离线 / 微软 / 第三方验证），而首页那份写成了二元 `account.Type == AccountType.Microsoft ? "微软账户" : "离线账户"`，Authlib 与 Offline 一起落进 else；账户页大卡片与账户列表行能显示对，只是各自恰好写对了，没有任何一处是权威。修法按票里维护者拍板的「一套映射，两套渲染」：新增唯一映射 `src/NebulaLauncher.App/ViewModels/AccountTypeDisplay.cs AccountTypeDisplay（:11）`，长标签由 `AccountTypeDisplay.BadgeOf（:14）` 给出，账户列表行的短标签由 `AccountTypeDisplay.ShortBadgeOf（:26）` 从长标签去掉「账户」后缀派生——不再写第二份 switch，两份字面量并存就还能各自漂移，那正是本单的成因；详情行「主机名 · UUID」由 `AccountTypeDisplay.DetailOf（:39）` 与 `AccountTypeDisplay.HostOf（:49）` 收敛，只有第三方验证账户带主机名，且只暴露 host。三处渲染改调同一份：首页徽标 `src/NebulaLauncher.App/ViewModels/HomeViewModel.cs AccountBadge（:663）`、首页详情 `HomeViewModel.cs:666`、账户页大卡片 `src/NebulaLauncher.App/ViewModels/AccountsViewModel.cs ActiveTypeLabel（:796）`、账户列表行 `AccountsViewModel.cs:961 TypeLabel`。
2. **一处顺带的重复消除。** 账户页原先私有的 `AuthlibDisplay` 并入 `AccountTypeDisplay` 后删除；「要不要带主机名」这个判断此前首页与账户页各留一份，现在只有 `DetailOf` 一处。行为上除修掉的偏差外与本版之前逐字一致：短标签去掉「账户」后缀后，列表行的视觉宽度与合并前相同（`[InlineData]` 里对三种类型逐条钉住）。

### 系统要求

- Windows 10 1809 及以上 / x64。
- zip 形态需要 .NET 8 Desktop Runtime（<https://dotnet.microsoft.com/download/dotnet/8.0>）；便携单文件形态自带运行时，不需要。
- 至少 200 MB 可用空间，游戏版本与实例另计。
- 启动 Minecraft 需要对应版本的 Java；启动器可在缺 Java 时一键安装。

对外版本号一律 `v1.0.3`，唯一来源是 `Directory.Build.props:9` 的 `<Version>1.0.3</Version>`；它同时决定 AssemblyVersion、FileVersion 与 InformationalVersion，设置页「关于」与崩溃导出的 `system.txt` 显示同一串，发布 tag 与发布目录名也跟着它走。

## 二、安装与体积

### 附件与实测体积

体积在本机 win-x64、Release 配置下由 `build.ps1 -Publish` 构建、`tar` 打包后实测（2026-10-25，tag `v1.0.3`）：

| 附件 | 形态 | 实测体积 | 文件数 | 前提 |
| --- | --- | --- | --- | --- |
| `NebulaLauncher-v1.0.3-win-x64.zip` | 框架依赖 + 单文件，原生库外置 | 压缩包 <<ZIP_BYTES>> 字节；解压后 <<ZIP_EXTRACTED_BYTES>> 字节 | 解压后 3 个 | .NET 8 Desktop Runtime |
| `NebulaLauncher-v1.0.3-win-x64-portable.exe` | 自包含 + 单文件 + 裁剪压缩 | <<PORTABLE_BYTES>> 字节（单文件，无解压步骤） | 1 个 | 无 |

zip 解压后 3 个文件、合计 <<ZIP_EXTRACTED_BYTES>> 字节：`NebulaLauncher.exe` <<EXE_BYTES>> 字节 + `libSkiaSharp.dll` <<LIBSKIASHARP_BYTES>> 字节 + `libHarfBuzzSharp.dll` <<LIBHARFBUZZ_BYTES>> 字节。便携形态没有解压步骤，<<PORTABLE_BYTES>> 字节就是那个单文件 exe。这些数字随 .NET 运行时版本与构建机变化。

### 安装与运行

- **zip**：解压到任意可写目录，双击 `NebulaLauncher.exe`。目标机缺 .NET 8 Desktop Runtime 时 Windows 会提示安装；装好后不需要 `%TEMP%` 写权限。
- **portable exe**：放到任意目录双击，无需解压、无需运行时。首次启动把原生库解压到 `%TEMP%\.net\NebulaLauncher\`；该目录被安全软件或策略拦截时启动会直接失败，改用 zip，或设置环境变量 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向一个可写目录。
- 两种形态共用同一份数据目录（默认 `%APPDATA%\NebulaLauncher`），可以互换使用。
- 可执行文件未签名，Windows SmartScreen 会弹「已保护你的电脑」：点「更多信息」，再点「仍要运行」。

### 校验

```powershell
# PowerShell
Get-FileHash .\NebulaLauncher-v1.0.3-win-x64.zip -Algorithm SHA256
Get-FileHash .\NebulaLauncher-v1.0.3-win-x64-portable.exe -Algorithm SHA256
```

```bash
# Git Bash / Linux，SHA256SUMS.txt 与附件放同一目录

```

`SHA256SUMS.txt` 全文（每行「64 位小写十六进制 + 两个空格 + 文件名」，行尾必须是 LF：CRLF 会让 `sha256sum -c` 把 `\r` 算进文件名）：

```text

<<SHA_ZIP>>  NebulaLauncher-v1.0.3-win-x64.zip
```

## 三、已知限制

以下 8 条在 v1.0.3 的代码里确认存在，也是本版真正的功能缺口。每条后面的括号是代码位置指针。它们与 v1.0.2 相同：本版是单缺陷补丁版，只改账户类型文案的来源，未触及这些缺口。

1. **页面切走后旧页面的后台任务不回收。** 实例页、模组页打开定时刷新后切到别的页面，旧页面的定时器与订阅不会被拆掉；长时间来回切换会表现为刷新变密或偶发卡顿（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:327 InvalidatePageCache`）。
2. **快速连点导航时页面钩子可能交错。** 上一页的进入 / 离开准备工作是异步发起、不等结果的，连点左侧导航时偶发数据晚一拍，切换过快时看到的是上一页的旧数据（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs:649 RunPageLifecycleAsync`）。
3. **反复进出账户页会累积监听。** 账户变化通知的订阅只在页面销毁时退订，而缓存失效的路径不销毁页面，进入账户页次数越多，监听越多（`src/NebulaLauncher.App/ViewModels/AccountsViewModel.cs:265 Dispose`）。
4. **启动器运行中手改账户文件不生效。** 直接编辑 `accounts.json` 后，界面不会重新加载，需要重启启动器（`src/NebulaLauncher.Core/Abstractions/AccountServices.cs:19 ReloadAsync`；实现见 `src/NebulaLauncher.Core/Accounts/AccountService.cs:108 LoadAsync`）。
5. **按文件夹放开的资源包不被识别。** 资源包列表只认 `.zip` 与 `.resourcepack` 文件；把资源包解包成 `resourcepacks/<名字>/` 文件夹后不进列表（`src/NebulaLauncher.Core/Mods/ContentService.cs:1183 ScanFiles`、`ContentService.cs:1242 IsContentFile`）。
6. **并发导入同名整合包可能撞名。** 实例名唯一化是先查后建，两个同名整包同时导入的极端时序下会撞到同一个版本目录名（`src/NebulaLauncher.Core/Backups/ModpackService.cs:1798 ResolveUniqueVersionName`、`ModpackService.cs:1843 IsVersionNameTaken`）。
7. **继承型整包首次启动要补下载 client jar。** 导入的整包若引用原版版本，首启前会补一个约 20 MB 的 client jar，启动前有一条警告提示，进度停在准备阶段属于正常（`src/NebulaLauncher.Core/Backups/ModpackService.cs:588 WriteInheritedVersionJsonAsync`；告警来自 `src/NebulaLauncher.Core/Launching/PreflightChecker.cs:417 CheckLoaderAsync`）。
8. **换账户后实例面板的认证服务器文案滞后。** 已打开的实例设置面板仍显示上一个账户「跟随账户」的认证服务器，关掉面板重开或重启启动器后正确（`src/NebulaLauncher.App/ViewModels/VersionsViewModel.cs:1953 EditorAuthServerHint`）。本版修的是首页与账户页的类型徽标，这条「跟随账户」的提示来源不同，未一并改动。

## 四、证据链与签名说明

### 签名状态

本版可执行文件未使用代码签名证书签名，因此 Windows 可能显示「Windows 已保护你的电脑」：首次运行点「更多信息」→「仍要运行」。请用上一节的 SHA256 核对文件完整性后再决定是否运行（右键 → 属性 → 数字签名 为空属预期）。

### 发布可见性

仓库为私有仓库，未登录状态下访问本 Release 的网页地址返回 404，属预期；附件仅对拥有仓库访问权限的成员可见。发布命令只建草稿（`--draft`），「Publish release」由人在网页点。

### 产物自检

三道产物自检都在构建时执行，未使用 `-SkipVerify`，两种形态各自跑满三道：

- 第 1 关 `<out>\NebulaLauncher.exe --probe-dir <out>`：30 秒内退出码 0，输出含 `writable=YES`。
- 第 2 关 `--selftest-json`：120 秒内退出码 0、输出无 `json-selfcheck.FAIL`、且 `json-selfcheck.summary=7/7`；它真跑七条 JSON 落盘往返（`src/NebulaLauncher.Core/Diagnostics/JsonSelfCheck.cs JsonSelfCheck`）。
- 第 3 关 `--data-dir <out>\.verify --screenshot <out>\.verify.png --page home`：20 秒内退出码 0 且 PNG 大于 10240 字节（本版实测 <<VERIFY_PNG_BYTES>> 字节）。

第 2 关把单文件解包目录钉在产物目录（`DOTNET_BUNDLE_EXTRACT_BASE_DIR`），它的结论只反映产物本身，不受 `%TEMP%\.net` 可写性影响。

### 本版修复的自动化证据

`tools/TestRunner` 全量 2492 项通过，其中本版新增 20 项直接对应 #28：

- 首页渲染口径：`tests/NebulaLauncher.Tests/AppHome_AccountBadgeTests.cs`（6 条 Fact）。钉的是修复后的行为：第三方验证账户的徽标必须是「第三方验证」而不是「离线账户」；微软与离线两档保持原口径不被这次重构带偏；详情行只给第三方验证账户带主机名，API 根非法时退回纯 UUID；没有账户时卡片仍是空的。
- 映射本身与两套渲染的一致性：`tests/NebulaLauncher.Tests/AppAccounts_TypeDisplayTests.cs`（4 条 Fact + 3 条 Theory、10 个 `[InlineData]`）。钉的是「一套映射」这个前提：三种类型的长标签与短标签各自正确、短标签不因合并而变长、只有第三方验证带主机名、API 根非法或为 null 时不显示主机名、主机名只取 host 不带路径与查询串、账户列表行合并前后的显示逐字一致。
- 行数与参数化基线随新增用例同步：`tests/NebulaLauncher.Tests/DocsCheck_CountTests.cs` 的 `[InlineData]` 基线由 763 提到 773，总数由 2472 提到 2492——**只骗过其中任何一条都会红**：把首页判定改回二元，第一条文件里的「第三方验证」断言立刻失败；把短标签改回再写一份字面量，第二个文件里「短标签不因合并而变长」失败。
