# Nebula Launcher v1.1.0

v1.0.3 之后的皮肤功能版，2026-11-01 发布。本版把皮肤 / 披风管理从「明确不做」改判为已落地：网络皮肤库浏览、本地皮肤库、皮肤站换肤、官方微软账户换肤与披风切换、云端衣柜，以及支撑这些页面的纹理缓存与头像 / 3D 预览。改动集中在 `src/NebulaLauncher.App/Skinning/`、`src/NebulaLauncher.Core/Skinning/` 与皮肤页、账户页、首页的渲染层，安装与启动链路未改。本文件由 `gh release create v1.1.0 --notes-file docs/release-notes/v1.1.0.md` 直接读取（`CONVENTIONS.md` §8.7）。

## 一、概览

Nebula Launcher 是一个以 Windows 为首发验证平台的 Minecraft Java 版桌面启动器：原生 Avalonia 界面，不内嵌 WebView，把版本安装、实例与模组管理、启动、崩溃诊断收在同一个窗口里。

### 本版包含

1. **皮肤页与网络皮肤库浏览（票 #41）。** 皮肤页给出网络皮肤库的平铺卡片列表，按关键字与分页浏览；每张卡片可展开 3D 预览，预览卡可收起。页面逻辑在 `src/NebulaLauncher.App/ViewModels/SkinsViewModel.cs SkinsViewModel`，视图在 `src/NebulaLauncher.App/Views/SkinsView.axaml SkinsView`。
2. **本地皮肤库（票 #42）。** `<data>/skins/` 下的 PNG 可扫描、导入、删除、索引进 `index.json`，并按「全部 / 皮肤 / 披风」三态页签筛选；网络库的条目可下载收藏到本地。尺寸按游戏规则校验：宽必须是 64 的倍数、高是 32 的倍数，`slim` 只能恰好 64×64（`src/NebulaLauncher.Core/Skinning/LocalSkinStore.cs LocalSkinFormat.Validate`）。披风独立存于 `<data>/capes/`（`src/NebulaLauncher.Core/Skinning/LocalCapeStore.cs LocalCapeStore`）。
3. **皮肤站换肤（票 #43、#59）。** `src/NebulaLauncher.App/Skinning/AuthlibSkinClient.cs AuthlibSkinClient` 调用皮肤站的 Yggdrasil 路由上传皮肤与披风、删除材质；服务端返回 404 时按「路由不存在」与「材质不存在」给两种话术，删除按请求方法给指引（票 #59）。冷却提示按通道给称呼，皮肤站通道不再说「官方服务」（票 #52）。站点密码只在本机加密保存，落 `<data>/skin-site-credentials.json`（`src/NebulaLauncher.Core/Skinning/SkinSiteCredentialStore.cs SkinSiteCredentialStore`），可随时在界面删掉。
4. **官方微软账户换肤与披风（票 #44、#61）。** `src/NebulaLauncher.App/Skinning/MojangSkinClient.cs MojangSkinClient` 上传皮肤（`UploadSkinAsync`）、重置默认皮肤（`ResetSkinAsync`）、读取档案（`GetProfileAsync`）；披风只能切换或隐藏账户已拥有的条目（`SetActiveCapeAsync`、`HideCapeAsync`），官方没有披风上传接口。切账户与换肤并发时的忙碌状态在票 #61 收紧：操作完成后按当前账户复位，不再把上一个账户的忙碌态带过来。
5. **云端衣柜（票 #58）。** `src/NebulaLauncher.App/Skinning/CloudClosetClient.cs CloudClosetClient` 与 `src/NebulaLauncher.App/ViewModels/CloudClosetViewModel.cs CloudClosetViewModel` 走皮肤站的网页会话接口，而不是 Yggdrasil 上传路由：登录取 CSRF 令牌、`CookieContainer` 存会话，支持浏览自己衣柜、上传、应用、清除角色材质、下载到本地、删除自己传过的条目。入口是皮肤页第三个页签（`src/NebulaLauncher.App/Views/CloudClosetView.axaml CloudClosetView`）与侧边栏 3D 皮肤卡。
6. **纹理缓存落盘（票 #54）。** 进程内三个字典随页面释放清空；跨进程复用在 `<data>/cache/skins/`，读写统一走 `src/NebulaLauncher.Core/Skinning/SkinTextureStore.cs SkinTextureStore`：根上放内嵌默认皮肤 `default-steve.png` / `default-alex.png`，账户自有纹理落 `<uuid>/<hash>.png` 配 `current.json`，公开皮肤库落 `<站点主机名>/<hash>.png` 配 `<tid>.json`。落盘先写 `.tmp` 再 `File.Move` 覆盖，元数据最后落地当提交标记，半截 PNG 不会被当成有效缓存。断网启动时先前取过的账户皮肤和皮肤站纹理仍能 3D 预览（`src/NebulaLauncher.App/Skinning/SkinTextureLoader.cs SkinTextureLoader.LoadAsync`）。这层缓存按可重建物对待，清掉后下次打开页面自动重建；`<data>/skins/` 用户皮肤库不属于下载缓存。
7. **皮肤头像、侧边栏 3D 卡与窗口尺寸（地图 #46、票 #51）。** 账户页与首页账户卡片显示皮肤头像（`src/NebulaLauncher.Core/Accounts/SkinAvatarService.cs SkinAvatarService`、`src/NebulaLauncher.App/Controls/SkinAvatar.cs SkinAvatar`）；侧边栏加入 3D 皮肤卡；窗口最小尺寸按侧边栏内容自适应，侧边栏展开时不再把内容挤出窗口（票 #51）。换肤成功后经 `src/NebulaLauncher.App/Skinning/SkinChangeNotifier.cs SkinChangeNotifier` 广播独立的皮肤变更事件，头像、预览卡与 3D 卡各自订阅刷新，不再靠账户对象上的字段轮询。

### 系统要求

- Windows 10 1809 及以上 / x64。
- zip 形态需要 .NET 8 Desktop Runtime（<https://dotnet.microsoft.com/download/dotnet/8.0>）；便携单文件形态自带运行时，不需要。
- 至少 200 MB 可用空间，游戏版本与实例另计；皮肤纹理缓存按使用量增长，可在设置里按「下载缓存」清理。
- 启动 Minecraft 需要对应版本的 Java；启动器可在缺 Java 时一键安装。

对外版本号一律 `v1.1.0`，唯一来源是 `Directory.Build.props:9` 的 `<Version>1.1.0</Version>`；它同时决定 AssemblyVersion、FileVersion 与 InformationalVersion，设置页「关于」与崩溃导出的 `system.txt` 显示同一串，发布 tag 与发布目录名也跟着它走。

### 安装与运行

- **zip**：解压到任意可写目录，双击 `NebulaLauncher.exe`。目标机缺 .NET 8 Desktop Runtime 时 Windows 会提示安装；装好后不需要 `%TEMP%` 写权限。
- **portable exe**：放到任意目录双击，无需解压、无需运行时。首次启动把原生库解压到 `%TEMP%\.net\NebulaLauncher\`；该目录被安全软件或策略拦截时启动会直接失败，改用 zip，或设置环境变量 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` 指向一个可写目录。
- 两种形态共用同一份数据目录（默认 `%APPDATA%\NebulaLauncher`），可以互换使用；皮肤库与纹理缓存在该目录的 `skins/`、`capes/`、`cache/skins/` 下，两种形态共用。
- 可执行文件未签名，Windows SmartScreen 会弹「已保护你的电脑」：点「更多信息」，再点「仍要运行」。

## 三、已知限制

以下 10 条在 v1.1.0 的代码里确认存在：前 8 条是沿用自 v1.0.3 的功能缺口，本版未触及；第 9、10 条是本版新能力的边界，属于设计取舍而不是缺陷。每条后面的反引号是代码位置指针。

1. **页面切走后旧页面的后台任务不回收。** 实例页、模组页打开定时刷新后切到别的页面，旧页面的定时器与订阅不会被拆掉；长时间来回切换会表现为刷新变密或偶发卡顿（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs MainWindowViewModel.InvalidatePageCache`）。
2. **快速连点导航时页面钩子可能交错。** 上一页的进入 / 离开准备工作是异步发起、不等结果的，连点左侧导航时偶发数据晚一拍，切换过快时看到的是上一页的旧数据（`src/NebulaLauncher.App/ViewModels/MainWindowViewModel.cs MainWindowViewModel.RunPageLifecycleAsync`）。
3. **反复进出账户页会累积监听。** 账户变化通知的订阅只在页面销毁时退订，而缓存失效的路径不销毁页面，进入账户页次数越多，监听越多（`src/NebulaLauncher.App/ViewModels/AccountsViewModel.cs AccountsViewModel.Dispose`）。
4. **启动器运行中手改账户文件不生效。** 直接编辑 `accounts.json` 后，界面不会重新加载，需要重启启动器（`src/NebulaLauncher.Core/Abstractions/AccountServices.cs IAccountService.ReloadAsync`；实现见 `src/NebulaLauncher.Core/Accounts/AccountService.cs AccountService.LoadAsync`）。
5. **按文件夹放开的资源包不被识别。** 资源包列表只认 `.zip` 与 `.resourcepack` 文件；把资源包解包成 `resourcepacks/<名字>/` 文件夹后不进列表（`src/NebulaLauncher.Core/Mods/ContentService.cs ContentService.ScanFiles`、`ContentService.IsContentFile`）。
6. **并发导入同名整合包可能撞名。** 实例名唯一化是先查后建，两个同名整包同时导入的极端时序下会撞到同一个版本目录名（`src/NebulaLauncher.Core/Backups/ModpackService.cs ModpackService.ResolveUniqueVersionName`、`ModpackService.IsVersionNameTaken`）。
7. **继承型整包首次启动要补下载 client jar。** 导入的整包若引用原版版本，首启前会补一个约 20 MB 的 client jar，启动前有一条警告提示，进度停在准备阶段属于正常（`src/NebulaLauncher.Core/Backups/ModpackService.cs ModpackService.WriteInheritedVersionJsonAsync`；告警来自 `src/NebulaLauncher.Core/Launching/PreflightChecker.cs PreflightChecker.CheckLoaderAsync`）。
8. **换账户后实例面板的认证服务器文案滞后。** 已打开的实例设置面板仍显示上一个账户「跟随账户」的认证服务器，关掉面板重开或重启启动器后正确（`src/NebulaLauncher.App/ViewModels/VersionsViewModel.cs VersionsViewModel.EditorAuthServerHint`）。
9. **官方账户不能上传新披风。** 官方接口没有披风上传路由，客户端只能读取账户已拥有的 `capes[]` 并切换或隐藏其中一条（`src/NebulaLauncher.App/Skinning/MojangSkinClient.cs MojangSkinClient.SetActiveCapeAsync`、`MojangSkinClient.HideCapeAsync`）。想要新披风仍然要去 Mojang 官方渠道获取。
10. **皮肤站只支持一个站点地址，且上传依赖站点实现。** 站点列表管理与皮肤站注册都没做，只支持填一个站点地址；上传与删除要求站点实现 Yggdrasil 上传路由，littleskin 自身没实现，此时界面会提示去网页上传（`src/NebulaLauncher.App/Skinning/AuthlibSkinClient.cs AuthlibSkinClient.UploadSkinAsync`、`AuthlibSkinClient.UploadCapeAsync`）。云端衣柜不走 OAuth 授权码流程，无密码通道要等站方开放设备代码流白名单。

## 四、证据链与签名说明

仓库为公开仓库：本 Release 可匿名访问与下载，未登录状态下网页地址与 API 均返回 200，附件无需登录即可下载。发布命令直接创建已发布的 Release（不带 `--draft`），跑完即对外可见。

### 产物自检

发布脚本的三道产物自检在构建时执行，未使用 `-SkipVerify`，两种形态各自跑满三道：

- 第 1 关 `<out>\NebulaLauncher.exe --probe-dir <out>`：30 秒内退出码 0，输出含 `writable=YES`。
- 第 2 关 `--selftest-json`：120 秒内退出码 0、输出无 `json-selfcheck.FAIL`、且 `json-selfcheck.summary=10/10`；它真跑十条 JSON 落盘往返（`src/NebulaLauncher.Core/Diagnostics/JsonSelfCheck.cs JsonSelfCheck`）。
- 第 3 关 `--data-dir <out>\.verify --screenshot <out>\.verify.png --page home`：20 秒内退出码 0 且 PNG 大于 10240 字节（本版实测 minimal 146,137 字节、portable 146,116 字节）。

第 2 关把单文件解包目录钉在产物目录（`DOTNET_BUNDLE_EXTRACT_BASE_DIR`），它的结论只反映产物本身，不受 `%TEMP%\.net` 可写性影响。
