# NebulaLauncher 对照 PCL 的现状核查

审计日期：2026-10-23，按用户环境 America/Los_Angeles 记日；机器文件时间可能显示 10 月 24 日。

## 结论

**NebulaLauncher 已有大量真实业务实现，但不能认定 PCL 功能已经全部复刻完毕。** 原报告的“49 已覆盖 / 46 等价 / 0 未覆盖”统计的是文件职责对应，不能证明功能闭环、异常处理、跨平台行为或真实网络均完成。

本报告依据本地 PCL VB.NET/WPF 源码、Nebula C#/.NET 8/Avalonia 源码、本轮已有测试输出及截图。没有要求逐行照抄；使用 CmlLib、MVVM、async/await、Avalonia 原生控件都是合理实现方式。判断标准是用户能否完成同一任务、关键失败路径是否正确。历史文档里的“明确不做”“别再讨论”仅作为历史范围记录，不能把未实现的能力改记为“已完成”。

这是对报告中具名功能与主要调用链的核查，不是对 43,116 行 VB 的逐行形式证明，也不是全平台验收。表中的“有实现”与“真机已验证”分开记录。本轮后段按用户要求停止扩大改动和验证范围。

## 一、哪些是真做了

以下均能找到实际服务、调用入口或针对性测试，不是空页面或仅有接口。这里的“完成”只针对所列能力，不代表所在大模块没有其他缺陷。

| 能力 | 核查结果 | 主要证据与边界 |
|---|---|---|
| 11 个页面导航、深浅主题、设置绑定 | 已实现 | `MainWindowViewModel` 页面注册、各 View/ViewModel；占位页面类型存在不等于这些导航仍是占位页。没有逐像素复刻 PCL 控件 |
| 本地版本识别、正式/快照/远古/特殊分类、收藏/隐藏 | 已实现，有测试 | `Versions/VersionService`、`Models/Versions.cs`、`VersionFavorites`；不能由此推导在线安装所有版本都成功 |
| 原版及 Fabric/Quilt/Forge/NeoForge 安装、文件校验与修复 | 真实实现，验收不完整 | `Installing/InstallService*`、`NebulaGameInstaller`；历史真机证据仅涵盖原版 1.20.1，见后文 |
| Java 扫描、缓存、自动选取、缺 Java 安装入口 | 真实实现，有测试 | `Java/*`、`JavaProvisionPlanner`；本轮修正了两处加载器约束，不能称全部版本兼容性已实机认证 |
| 启动参数、实例级覆盖、前后命令、authlib 注入 | 真实实现，有测试 | `GameLauncher`、`JvmArgumentBuilder`、`LaunchOptionsFactory`、`AuthlibInjectorService`；显式进服参数冲突已修，退出生命周期仍有问题 |
| 实例隔离、克隆、回收站、备注、收藏和目录入口 | 已实现，有测试 | `Instances/InstanceService*`、`IsolationPolicy`；同 MC 版本换加载器已实现，不等同于 PCL 完整组件修改器 |
| 模组扫描、启停、多选批量、过滤、删除恢复 | 已实现，有测试 | `Mods/ContentService`、`ContentBatch`、`ModMetadataReader`；不是 `PageDownloadModify` 的等价替代 |

| 整合包导入与导出 | 真实实现，但不能概括为全部格式完整 | `ModpackService`、`ModpackExporter`；本轮补 MR/CF/MCBBS 缺口；导出实际是 `.mrpack`，不能用启动脚本或配置包证明整合包导出等价 |
| 崩溃分析、报告导入、脱敏导出、hs_err 收集 | 已实现，有规则测试 | `CrashAnalyzer`、`CrashRules`、日志页；UI 最终退出判断没有完全沿用 Core 判据 |
| 世界列表、NBT 编辑、手动备份/恢复、缩略图 | 已实现，有测试 | `Backups/*`；属于 Nebula 自有扩展较多，不能计作“抄完 PCL”的证据；自动备份本轮修复但仍有并发/元数据边界问题 |
| 服务器列表、servers.dat 导入、Ping、Query、进服入口 | 真实实现，有协议测试 | `Servers/*`、`ServersViewModel`；Ping 阻塞/IPv6 地址族已修，图标展示、持久化失败、启动地址解析仍有缺口 |
| 下载队列、暂停继续、限速、源测速与回退 | 真实实现，有测试 | `Downloads/*`；不是所有启动补全请求都走此队列，不能写“全链路统一” |
| 配置迁移、存储扫描清理、日志增量跟随 | 已实现，有测试 | `Transfer/ProfileBundleService`、`Maintenance/*`、`LauncherLogReader`；配置迁移刻意不含账户令牌，不能当整实例迁移 |
| Windows 托盘、任务栏进度、游戏窗口标题/最大化、高性能 GPU | Windows 有真实实现 | `Platforms/PlatformService`、`TrayService`；这些 Windows 行为不能证明 macOS 对应能力完成 |

|---|---|---|
| P1 | 启动时自动补全绕过统一下载链，设置代理/源与正式安装可能行为不同 | 静态确认：`GameLauncher` 默认 `new MinecraftLauncher(...)` 后 `InstallAndBuildProcessAsync`；`InstallService.CreateLauncher` 才注入 HttpClient 和 NebulaGameInstaller。应共用 launcher 工厂 |

| P1 | 窗口关闭同步等待保存，磁盘慢时阻塞 UI | 静态确认：`MainWindow.axaml.cs:270` 的 `SaveAsync().GetAwaiter().GetResult()`。应异步关闭协调，并在完成后再次退出 |

| P2 | 备份元信息写入失败后自动备份可能永不轮转 | 静态确认：`WriteMetaAsync` 吞异常；无 meta 的 ZIP 被保守当手动备份。应让归档与元信息形成明确提交状态，不能只记录日志后报告完整成功 |

| P2 | 服务器 favicon 读到了但没展示 | Core 有 FaviconBase64，服务器行 VM/XAML 未接通；不应将“解析字段”写成“完整图标支持” |

## 六、语言与平台差异

- WPF 控件 → Avalonia 控件/主题、LoaderTask → Task/取消/进度、settings.ini → 类型化 JSON，可以是合理替代；不需要为了“像 PCL”重写成熟框架。
- “框架支持”不能替代用户能力：ICommand 不自动支持 PCL 自定义主页事件格式，标准 ListBox 不自动证明所有 PCL 列表交互都覆盖。
- Windows 游戏窗口标题/最大化/句柄探测有实现；非 Windows 对应分支返回 null/false。启动器自身的 Avalonia 窗口最大化是另一件事，不能混淆。
- Windows 令牌主要使用 DPAPI；非 Windows 是 Base64 编码，未接 Keychain/SecretService。Windows DPAPI 失败也有 Base64 回退；现有警告只看平台能力，不能完整反映实际回退状态。
- 非 Windows 有剪贴板命令实现，并非所有平台代码都是空壳；需要逐能力判断，不能反向概括为“跨平台全部没做”。
